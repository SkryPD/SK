# 楼顶通用三维空间真值模型设计规格

## 目标

把已确认的楼顶整层灰模 v04 转换为可追溯、可重复生成的通用三维模型包，供空间关系核对、机位检查和后续硬装设计使用。模型不是施工图，也不替代现场复尺、结构、消防、机电、门窗或设备厂家深化。

## 已选方案

采用参数化通用模型包：

- `GLB`：主交换与网页预览文件，保留对象名称、图层和状态元数据。
- `OBJ + MTL`：用于导入不同三维软件；文件名明确标记毫米单位。
- 本地 Three.js 查看器：支持旋转、缩放、图层开关、对象点选和预设机位。
- JSON 清单与核验报告：记录来源、坐标转换、对象边界、文件哈希和已知限制。

不采用只做网页视觉模型的路径，因为难以在其他软件继续使用；不直接从旧 DWG 全量拉伸，因为现场复尺和业主确认已经覆盖了部分旧图关系。

## 权威输入

按以下顺序处理冲突：

1. 2026-10-10 业主确认的茶室 A/C/B/D/E 拓扑。
2. 现场复尺真值台账与两级吊顶确认记录。
3. `楼顶整层灰模_v04_坐标场景.json`。
4. DWG/PDF 仅用于 v04 未改动的既有壳体关系。
5. 旧效果图和历史灰模只作视觉参考，不提供尺寸。

主输入文件：

`output/空间真值/整层灰模/候选_v04_20261010/楼顶整层灰模_v04_坐标场景.json`

## 坐标与单位

- 源坐标单位为毫米，平面为本项目局部 `X/Y`，竖向为 `Z`。
- GLB 使用米，并按 glTF 的 Y-up 规则映射：`glTF X = local X / 1000`、`glTF Y = local Z / 1000`、`glTF Z = local Y / 1000`。
- OBJ 顶点使用毫米，并采用同一 Y-up 轴映射；文件名带 `_mm`，README 明确导入单位为毫米。
- 全局模型嵌入坐标只服务于空间校核，不得作为施工放样坐标。
- 公共室内、茶室和露台完成地面统一位于 `Z=0`。

## 模型范围

### 本版建立

1. `existing_floor_shell`
   - 西侧室外露台、公共大厅、面山露台带、东端过渡区和茶室地坪。
   - 地坪采用无厚度平面，不虚构结构板厚。
2. `existing_core_walls`
   - 卫生间、楼梯、电梯/井道按 v04 已有边界建立体块。
   - 当前属于空间占位体块，不宣称已经拆分为施工级墙体和门洞。
3. `existing_steel_columns`
   - C1-C4 四根钢柱，截面 `105×150mm`，按 C 点锚定的确认链放置。
4. `approved_fixed_design`
   - 茶室共同墙、唯一窗墙的墙垛/窗台/窗头、背景实墙、露台侧边界墙。
   - `A-C=3000mm` 开放通道不生成门、门框、门楣或实体墙头。
   - 吧台 `5030×800×1000mm`、800mm 上下翻门、设备段及设备架。
   - 设备段按 E1-E5 分块生成，避免总设备体块与设备架重叠。
5. `design_ceiling`
   - 茶室全域 `2450mm` 控制面。
   - 茶室以外室内 `2700mm` 控制面。
   - 默认关闭，可在查看器单独开启。
6. 空图层
   - `existing_roof_truss`：保留层名和“需现场复尺”状态，不生成假几何。
   - `future_glass_system`：保留层名，当前不生成玻璃或门扇。

### 本版排除

- 钢屋架、压型钢板、消防管及未复尺梁体的三维几何。
- 给排水、地漏、插座、开关、灯具、风管和设备管线。
- 活动桌椅、人物、植物、软装和正式饰面。
- 未来玻璃门的分格、轨道、开启方式和收纳位置。
- 未经确认的墙厚、楼板厚度、结构节点和施工收口。

## 几何生成规则

- `floor` 输出为双面三角平面，保持零厚度。
- `wall`、`steel_column` 和确定的 `fixed_fixture` 按边界框和确认高度生成独立网格。
- 茶室窗不做布尔猜测；利用已拆分的墙垛、窗台和窗头对象自然形成唯一窗洞。
- `opening_control` 不生成实体，只写入 GLB 节点/清单元数据并在查看器以辅助线标识。
- `bar_body` 与 `bar_flip_gate` 拆分显示：翻门使用源边界 `[35040,1130,35840,1930]`，固定吧台段使用 `[35040,1930,35840,6160]`，禁止重叠面。
- `equipment_run` 不作为一整块实体输出；从源边界Y=1760向Y=6160依次排列E1-E5并闭合4400mm设备链，其中E1-E4高900mm，E5采用已确认设备架边界和1800mm高度。
- `room_volume` 输出为低饱和灰色占位体块，并在元数据中标记 `derived_massing`。
- 每个对象保留 `id`、中文名称、图层、状态、来源和源边界；未知项不得被自动升级为 `verified`。

## 查看器

查看器使用本地 Three.js 文件，不依赖在线 CDN。首屏为全画布三维场景，侧栏仅承担图层、对象信息和视角切换，不叠加装饰性卡片。

功能包括：

- 轨道旋转、平移、滚轮缩放、回到全景。
- 按图层显示/隐藏。
- 点选对象显示名称、尺寸、状态和来源。
- 切换正交俯视、轴测、V01-R1、V02-R1 四个预设视角。
- `requires_site_measurement` 与 `user_decision_required` 使用明确警示色。
- 茶室窗顶2750mm与2450mm天花的300mm冲突保持可见，不自动修正。

V01-R1 与 V02-R1 相机只用于视觉校核：

- V01-R1：吧台中部向图纸左侧看公共大厅和西侧露台。
- V02-R1：公共大厅中部向图纸右侧看吧台。
- 相机眼高和精确坐标属于显示参数，不进入施工尺寸台账。

## 生成架构

1. 读取 v04 场景 JSON。
2. 校验版本、关键对象、坐标范围和硬约束。
3. 将场景对象转换为统一中间网格表示。
4. 从同一中间表示分别写出 GLB、OBJ/MTL 和 manifest，避免两种格式漂移。
5. Three.js 查看器加载 GLB，并从节点 `extras` 读取图层与状态。
6. 自动检查文件结构和包围盒，再用浏览器截图完成视觉核验。

## 错误处理

- 输入版本不是 `rooftop-whole-floor-truth-model-v04` 时停止生成。
- A/C/B/D/E、四根钢柱、茶室唯一窗、吧台或设备链缺失时停止生成。
- 出现负尺寸、零面积实体、非有限坐标或设备链不闭合时停止生成。
- 未识别对象只写入报告，不静默丢弃或猜测生成。
- 输出写入独立候选目录，不覆盖 v04 灰模或历史三维版本。

## 自动验收

- A/C/B 共线，C-E 与 B-D 平行，E-D 与露台侧边界重合。
- 茶室净域为 `3200×4100mm`；唯一窗为 `3220×2400mm`，窗台350mm。
- 四柱三跨对象数量和边界与 v04 JSON 一致。
- 吧台、上下翻门、E1-E5 设备链无重叠重复实体。
- GLB 可解析，场景节点、图层、对象 extras 和总包围盒符合清单。
- OBJ 顶点/面索引有效，组名和 MTL 引用完整。
- GLB 与 OBJ 由同一中间场景生成，关键对象包围盒换算后相等。
- v03、v04 二维灰模测试继续通过，历史文件未被覆盖。

## 视觉验收

- 使用 Playwright 检查桌面与手机视口，画布非空，模型完整入镜，控件与文字不重叠。
- 俯视图能辨认大厅、露台、茶室、吧台、核心筒和四柱列。
- 轴测图无旧茶室矩形、额外内墙、错误门洞或设备墙后方空间。
- V01-R1 不把吧台错误放入主画面；V02-R1 能读出吧台、操作通道、完整设备背景墙和右后方茶室。
- 每项硬约束记录为 `pass`、`fail`、`uncertain` 或 `not_visible`；关键项出现 `fail` 时不得转正。

## 候选状态与使用边界

首版状态为 `candidate_requires_clash_decision`。只有模型文件、自动检查和四视角视觉核验全部通过，并经业主确认后，才能转为后续硬装设计的正式空间基底。模型中的全球坐标、占位体块和显示参数均不得用于施工放样。
